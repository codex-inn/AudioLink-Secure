# AudioLink Secure

Consent-based live audio streaming between authorized Windows desktops, using WebRTC for encrypted media and a small FastAPI signaling service hosted on Render.

> **Safety model:** the sender must explicitly start sharing and approve receiver requests. Capture status stays visible. This MVP does not support covert capture or unattended microphone access. Persistent trusted-device pairing/revocation is planned for a later milestone with durable storage.

## MVP features

- Browser-based sender/receiver UI served by FastAPI.
- Short pairing code generated by the sender.
- Sender explicitly approves each receiver connection.
- Microphone sharing and optional system audio via the browser's screen-share picker (Chrome/Edge support varies; choose the system-audio option when available).
- WebRTC media encryption in transit.
- Visible capture/connection status and stop controls.
- Render deployment blueprint.

## Local development (Windows 10/11)

1. Install Python 3.11+.
2. Open PowerShell in this repository.
3. Create a virtual environment and install dependencies:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

4. Start the server:

   ```powershell
   uvicorn server:app --host 127.0.0.1 --port 8000 --reload
   ```

5. Open `http://127.0.0.1:8000` in Edge or Chrome. For two local devices, use the host computer's LAN address for the second browser. For internet testing, deploy the signaling server and use a TURN service if direct WebRTC connectivity fails.

## Render deployment

- Create a new Render **Web Service** from this repository.
- Render can use `render.yaml` automatically.
- The service listens on Render's `$PORT`.
- Use HTTPS in production. WebRTC audio is encrypted, but signaling and pairing metadata still require secure transport.

## Important limitations

- Pairing approvals are in-memory in this first milestone and are lost when the server restarts.
- This MVP does not yet implement persistent trusted-device tokens, account login, or a TURN relay. Do not expose it as a production service until those features, rate limiting, and security review are complete.
- System audio capture depends on browser/OS support and requires the user to select the appropriate screen/window and audio-sharing option.
- The sender must remain aware of active capture; stop sharing to end audio capture.

## Project roadmap

1. MVP: explicit pairing and live WebRTC audio.
2. Add durable account/device identity and revocable persistent pairing using a database.
3. Add TURN configuration, rate limiting, session expiry, audit events, and tests.
4. Package a Windows desktop shell only after the web MVP is security-reviewed.
